# 수도권 머니 플라이트

수도권 77개 시군구(서울 25구 · 인천 10군구 · 경기 42시군구) 사이에서 아파트 매매 자금, 전월세 보증금, 인구가
어디서 어디로 움직이는지 항공 관제판처럼 보여주는 정적 웹 서비스.

```bash
python3 pipeline/run.py demo                                   # 데모 데이터 → dist/index.html
MOLIT_KEY=... python3 pipeline/run.py real --from 2024-01 --to 2026-08
python3 -m unittest discover -s tests                         # 테스트
```

실데이터 모드에 필요한 수동 다운로드 자료:

| 파일 | 출처 |
|---|---|
| `data/raw/reb_buyer_residence.csv` | 한국부동산원 R-ONE 「매입자거주지별 아파트매매거래」 시군구·월 |
| `data/raw/mdis/*.csv` | 통계청 MDIS 「국내인구이동통계」 마이크로데이터 (재배포 금지, 커밋 금지) |

### 지역 상세 분석에 쓰는 자료 (선택)

| 화면 | 파일 | 출처 | 기준 |
|---|---|---|---|
| 단지별 매매·전월세 순위 | (국토부 API에서 함께 집계) | 실거래 응답의 단지명·법정동·지번·면적 | 단지 식별: `aptSeq` 있으면 사용, 없으면 시군구+법정동+지번+단지명 |
| 근로소득 | `data/raw/nts_income.csv` | 국세청 TASIS「시군구별 근로소득 연말정산 신고현황(주소지)」 | 연 단위, N년 귀속분이 N+1년 12월 공개 |
| 카드 지출(서울) | `data/raw/card_seoul.csv` | 서울 열린데이터광장 OA-23094 (서울시·신한카드) | **거주지** 행정동, 월 |
| 카드 지출(경기) | `data/raw/card_gyeonggi.csv` | 경기데이터드림「카드 소비 데이터」 | 시군구, 가맹점 기준으로 추정(명세 확인 필요) |
| 카드 지출(인천) | `data/raw/card_incheon.csv` | 인천e음 군구별 결제금액 | 지역화폐만, 신용카드 전체 아님 |

카드 지출은 시도마다 집계 기준이 달라 금액을 서로 비교하면 안 된다. 화면은 기준을 항상 함께 표시한다.
열 이름은 실제 파일로 확인하지 못했다. `sources/nts_income.py`, `sources/card.py` 맨 위 `COLS`에서 맞춘다.

## 구조

```
pipeline/
  build_geo.py       행정동 경계 → 시군구 병합·단순화 (data/regions_geo.json)
  regions.py         시군구 앵커 좌표(아파트 밀집지 보정), 데모용 사전값
  leverage.py        자기자본 추정용 대출 가정 (LTV, 주담대 한도, 이용률)
  sources/molit.py   국토부 실거래 매매·전월세 API → 시군구·월 집계 (캐시, 병합 저장)
  sources/reb.py     부동산원 매입자거주지별 매매 CSV → 버킷 비중
  sources/mdis.py    통계청 인구이동 마이크로데이터 → 시군구 OD (주택 사유)
  synth.py           위와 '같은 스키마'의 데모 중간 테이블 생성
  build_flows.py     중간 테이블 → 흐름 추정 → data/flows.json
  build_detail.py    단지·소득·카드 → 지역별 상세 파일 data/detail/{code}.json
  build_web.py       flows.json 인라인 → dist/index.html
  run.py             진입점 (demo | real)
web/template.html    UI (Canvas 2D, 외부 JS 의존성 없음)
tests/               로더·모형 불변식 테스트 (표준 unittest)
```

지역 상세 파일(77개, 합계 약 5MB)은 지역을 누를 때만 받는다. 첫 화면 HTML에 넣으면 2MB가 7MB로 커진다.
`dist/`는 정적 호스팅에 그대로 올리면 되지만, `file://`로 열면 브라우저가 상세 파일 요청을 막으므로
로컬에서는 `python3 -m http.server -d dist`로 띄운다.

데이터는 월 1회 갱신되므로 상시 API 서버 없이 **월 배치 → 정적 파일 → CDN** 구조로 충분하다.
`dist/`와 `data/flows.json`은 빌드 산출물이라 커밋하지 않는다(월마다 2MB씩 이력이 불어남). CI가 만들어 artifact로 올린다.

## 흐름 추정 방법

실거래 자료에는 매수자의 출발지가 없다. 따라서 **인구 이동만 실측 OD이고, 매매·전월세는 추정**이다.

| 레이어 | 식 |
|---|---|
| 매매 자금 | `F(i→j) = 거래건수(j) × 매입자거주지비중(j, 버킷) × 이주OD(i→j) / Σ버킷 이주OD` |
| 매매 자기자본 | 위와 같은 배분 × 건별 `가격 − 0.65 × min(LTV × 가격, 한도)` |
| 전월세 보증금 | `신규계약(j) × 이주OD(i→j) / Σ_i 이주OD(i→j)` |
| 인구 이동 | MDIS OD 그대로 (주택 사유) |

- 버킷은 부동산원 분류(관할 시군구 내 / 시도 내 / 서울 / 기타). 후보 출발지가 없는 버킷의 비중은 나머지에 재배분한다.
- 이주 OD는 최근 12개월 누적. 인구이동은 실거래보다 늦게 공개되므로, **그 달 이전에 실제로 존재하는** 최근 12개월을 쓰고
  사용 기간을 `meta.od_window`에 남긴다. UI 안내판 하단에 그 기간이 표시된다.

### 모형이 반드시 지키는 조건 (tests/test_model.py)

- 지역 j로 들어온 매매 흐름 합 = j의 실거래 건수
- 서울 출발분 합 = 거래건수 × '서울 거주자' 비중
- 자기자본 레이어의 건수 = 매매 레이어의 건수, 금액 합 = 지역 자기자본 합
- 전월세 유입 합 = 신규 계약 수
- OD가 없는 달에도 배분이 균등분포로 무너지지 않음, OD가 아예 없으면 실패

## 수집 비용과 캐시 정책

공공데이터포털 API는 무료지만 일일 호출 한도가 있고, 77개 지역 × 개월 수 × 2개 API를 전부 다시 받으면 오래 걸린다.
그래서 응답을 `data/raw/molit/`에 저장해 재사용한다. 단, 실거래 자료는 받은 뒤에도 바뀐다.

- 신고기한: 계약일부터 30일 → 그 사이 건이 계속 늘어난다
- 해제 신고: **해제 확정일부터 30일**. 계약일 기준 상한이 없어 몇 달 뒤에도 해제 표시가 붙을 수 있다
- 정정 신고(가격·면적), 등기일 추가

| 계약월 나이 | 다시 받는 주기 (`molit.RefreshPolicy`) |
|---|---|
| 0~3개월 | 1일 (같은 날 재실행은 캐시) |
| 4~12개월 | 30일 |
| 13개월 이상 | 180일 |

- 다시 받을지는 (API, 지역, 월) 묶음 단위로 판단하고, 다시 받으면 모든 페이지를 교체한다. 받다 실패하면 옛 캐시를 유지한다.
- 다시 받을 때마다 이전 응답과 비교한 변경 건수(추가·삭제·해제·가격 정정·기타)를 `data/raw/molit_changes.csv`에 남긴다.
- 위 구간 경계는 출발점일 뿐이다. 실데이터가 쌓이면 `python3 pipeline/cancel_lag.py`로
  해제 시차 분포(계약일 → 해제일 + 신고 30일)와 나이별 변경 비율을 보고 `RefreshPolicy(warm=...)`를 조정한다.
- 소득·카드는 API가 아니라 공개 파일이다. 원천 파일의 내용 해시를 `data/raw/manifest.json`에 기록해 바뀌었을 때만 다시 적재한다.
- 전체를 강제로 다시 받으려면 `--refresh-all`.
- 월간 자동 실행(GitHub Actions 등)으로 옮길 때는 `data/raw/`를 실행 간에 보존해야 한다(actions/cache 또는 오브젝트 스토리지).
  보존하지 않으면 매번 캐시가 비어 전체를 다시 받는다.

## 인구이동 공개 시차와 자동 갱신

인구이동 통계는 실거래보다 늦게 공개된다. 공개 전인 달은 다음처럼 처리한다.

- **매매·전월세 흐름**: 출발지 배분 가중치로 '그 달 이전에 공개된 최근 12개월' 인구이동을 쓴다(`meta.od_window`).
- **인구 이동 레이어**: 그 달 이전 최신 공개월 자료로 대체 표시한다(`meta.move_src`, 데이터 복사 없이 대응표만 기록).
  지도·지표·안내판에 "2026.05 자료"처럼 원천 월을 표시하고, 전월 대비는 원천 월의 전월과 비교한다.
  타임라인 막대는 점선 빈칸으로 둔다(복사한 값으로 막대를 그리면 그 달에 실제 이동이 있었던 것처럼 보인다).

새 달 공개 감지와 반영:

1. `.github/workflows/check-updates.yml` 이 매일 KOSIS에서 최신 공개 월을 확인한다(저장소 Secrets에 `KOSIS_KEY` 필요).
2. `data/coverage.json`(실데이터 빌드 때 생성, 커밋 대상)보다 새 달이 나왔으면 GitHub 이슈로 알린다. 같은 제목의 열린 이슈가 있으면 만들지 않는다.
3. 시군구 OD는 MDIS 마이크로데이터라 로그인·이용 신청이 필요해 자동으로 받을 수 없다. 받은 파일을 `data/raw/mdis/`에 넣고
   `python3 pipeline/run.py real`을 돌리면 파일 해시로 변경을 감지해 다시 적재하고, 대체 표시가 자동으로 사라진다.

`sources/kosis.py`의 통계표 설정(`TABLE`)은 실제 키로 확인하지 못했다. KOSIS 통계표 화면의 OpenAPI 버튼에서 확인해 맞춘다.

## 데이터 품질 처리

| 문제 | 처리 |
|---|---|
| 계약 해제 신고 | `cdealType == 'O'` 제외 |
| 전월세 갱신 계약 | 흐름에서 제외, 집계에는 포함 |
| 부천시 2024 구 재설치 (41192/4/6) | 41190으로 병합 |
| 실거래 신고기한 30일, 늦은 해제·정정 | 계약월 나이별 재수집 주기, 최근 2개월 '잠정' 표시 |
| 일일 호출 한도·수집 시간 | 응답 캐시, (API, 지역, 월) 묶음 단위 교체, 오류 응답은 캐시 안 함 |
| 일부 기간만 재수집 | (ym, code) 병합 저장으로 과거 이력 유지 |
| 넓은 시군의 기하 중심 (화성 → 서해안) | 아파트 밀집지 앵커로 보정 |
| 비수도권 집계 노드 과대 표시 | 기본 꺼짐, 끄면 지도 색·KPI에서도 제외 |
| 인구이동 미공개 달 | 직전 가용 12개월로 배분, 인구이동 레이어는 최신 공개월로 대체 표시 |

## 한계

- 거래금액 ≠ 실제 이동 현금. 자기자본 레이어는 **정책 발표를 단순화한 가정**(`leverage.py`)에 기반하며
  DSR, 주택 수, 생애최초 특례, 승계 전세금(갭투자)을 반영하지 않는다. 운영 전에 정책 원문과 대조 필요.
- 법인 매수는 지역 정보로만 표시하고 흐름 배분은 개인과 같다. 외국인 미구분.
- R-ONE 통계표 열 이름(`sources/reb.py: COLS`)과 MDIS 전입사유 코드(`sources/mdis.py: HOUSING_REASON`)는
  실제 파일로 한 번 확인해야 한다. 이 저장소의 테스트는 문서 기준 형식으로 작성됐다.
- 경계 자료는 2023.07 기준.
